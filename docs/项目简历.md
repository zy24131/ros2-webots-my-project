# 面向复杂地形多轮腿式平台的 ROS2 运动控制中间件

**2025 年 — 2026 年　|　学生负责人 / 核心开发者**

作为该项目核心成员，我主导设计与实现了基于 ROS2 Humble 的分层运动控制栈，面向窄/宽轮距切换、多模式转向与原地自转等复杂工况，完成 Webots 仿真与真机可替换 IO 层的统一架构，保障多模块协同下的**意图清晰、执行可追踪、命令链路单一**。

技术栈：ROS2（Topic / Service / Action / Parameter / Timer）、C++17、Webots、colcon。

---

## ROS2 混合通信与接口设计

1. 主导设计 **Motion / Track 双域通信模型**，按业务语义拆分接口，避免「意图」与「执行」混用：
   - **Topic**：连续控制流（`steering_input`、`steering_command`、`joint_commands`、`wheel_speeds`、`mode`）
   - **Service**：一问一答意图下发（`SetMotion` 转向/自转意图，`SetTrack` 轮距意图）
   - **Action**：长时任务与进度反馈（`SetTrackAction` 窄/宽轮距伸缩，含 progress / success / cancel）
2. 封装 `my_robot_msgs` 自定义消息层（`SteeringCommand`、`WheelSpeeds` 等），统一 8 关节转向链与 4 轮速链的数据格式；Action 与 Service 同名空间分离（`SetTrack.srv` / `SetTrackAction.action`），消除 C++ 类型冲突。
3. 建立 `fsm/topic_names.hpp` 话题/服务/Action **名称 SSOT**，各节点不再硬编码字符串，降低联调与重构成本。

---

## 公共配置与 QoS 模块

1. 将分散的 `*_params.yaml` 合并为 **`fsm/config/my_robot.yaml` 唯一参数源**，Launch 通过 `params_file` 注入各节点；共享参数（如 `wide_neutral_angle_deg`）置于 `/**:` 段，节点专有参数分域管理。
2. 实现 `fsm::QoSFromParams()`，支持按端点配置 `reliable` / `sensor_data` 等 QoS profile，适配方向盘高频输入与模式切换的可靠性需求。
3. 建立 `fsm/joint_config.hpp` 关节索引 SSOT（`steering_index` / `wheel_speed_index` / `webots_index` 三套命名），消除各节点重复维护关节表的问题。

---

## FSM 状态机与 Trigger 调度

1. 设计 **case 0~5 显式 Trigger 驱动状态机**（`narrow_track` / `switch_to_wide` / `wide_track` / `switch_to_narrow` / `spin_left` / `spin_right`），意图（`motion_`、`track_intent_`）与 FSM 状态解耦，仅在 Trigger 条件满足时迁移。
2. 实现 **Service 存意图 → FSM 判差 → Action 执行** 的 Track 切换链路：HMI 调用 `SetTrack` 仅更新意图；FSM 检测当前轮距与意图不一致后，通过 `TrackActionClient` 发起 `SetTrackAction`；Action 完成后回调更新稳定态，失败自动回滚。
3. 抽取 `TrackActionClient`（goal 生命周期、取消、结果回调），FSM 主逻辑与 Action 通信细节分离，便于后续扩展自转 Action（姿态就绪门控 + 轮速使能）。

---

## actuator_control 执行与仲裁层

1. 设计 **唯一 `joint_commands` 发布者** 模型：`steering_control` 输出期望姿态，`actuator_control` 合并 SteeringCommand 与 SetTrackAction 插值命令后统一下发，避免多节点争用执行器。
2. 实现 `TrackTask` 无 ROS 依赖执行体（步进插值、到位判定、progress 计算）**配合 ROS2 Action 使用的任务执行体**。，Action Server 仅负责 ROS 胶水层，核心算法可单测。
3. 内置 **450ms 命令看门狗**：`steering_input` 超时后关节命令自动归零，防止仿真/真机在无操作员输入时保持危险姿态。

---

## 业务节点与算法层

1. **`robot_kinematics`（纯 C++ 算法库）**：窄/宽轮距曲率映射（`map`）、原地自转映射（`map_spin`）、曲率换算；与 ROS 解耦，供 `steering_control` 调用。
2. **`steering_control`**：订阅 `/my_robot/mode` 与方向盘输入，20ms 周期输出 `SteeringCommand`；宽轨死区内自动回中立角，切换态停止输出。
3. **`wheel_speed_control`**：四轮差速 Topic 链路已打通（当前占位输出 0，待接入曲率差速逻辑）。
4. **`hardware_bridge`（L1 IO 层）**：Webots 控制器桥接 `joint_states` / `joint_commands` / `wheel_speeds` / IMU；真机侧可替换为阀控/PLC 驱动，上层 L2/L3 无需改动。

## 仿真集成与工程化

1. 提供 **`run_webots.sh` 一键编译 + 启动** Webots 实时仿真；`hardware_bridge` 构建产物 install 至 `webots/controllers/ros2_bridge/`，wrapper 脚本自动 source ROS 环境与参数文件。
2. Launch 分层：`my_robot.launch.xml` → `control_bringup.launch.xml`，四节点（fsm / steering_control / actuator_control / wheel_speed_control）与参数文件解耦。
3. 文档体系：`steering_flow.md`（数据流）、`ros2_communication.md`（通信机制选型）、`架构说明.md`（分层对照），支撑团队 onboarding 与答辩展示。

## 项目亮点（简历一句话）

> 基于 ROS2 构建 L1~L3 分层运动控制栈，以 **Service 表达意图、Action 执行长任务、Topic 承载连续控制**，实现窄/宽轮距切换、多模式转向与 Webots/真机 IO 可替换架构；通过 SSOT 配置、Trigger FSM 与唯一命令发布者设计，保证复杂工况下控制链路清晰、可扩展、可维护。
